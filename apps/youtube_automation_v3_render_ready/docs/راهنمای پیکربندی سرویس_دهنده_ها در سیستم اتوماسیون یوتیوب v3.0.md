# راهنمای پیکربندی سرویس‌دهنده‌ها در سیستم اتوماسیون یوتیوب v3.0

**تاریخ:** 12 اکتبر 2025

**تهیه‌کننده:** Manus AI

این راهنما نحوه پیکربندی سرویس‌دهنده‌های مختلف (مانند YouTube API، LLMها، سرویس‌های تولید ویدئو و آپلود) را در سیستم اتوماسیون یوتیوب نسخه 3.0 (YouTube Automation System v3.0) توضیح می‌دهد. این پیکربندی‌ها از طریق متغیرهای محیطی (Environment Variables) انجام می‌شوند که باید در فایل `.env` (برای توسعه محلی) یا در پلتفرم استقرار (مانند Render.com) تنظیم شوند.

## 1. پیکربندی کلی متغیرهای محیطی

پروژه از فایل `.env.example` به عنوان یک الگو برای متغیرهای محیطی استفاده می‌کند. برای پیکربندی سرویس‌ها، باید متغیرهای مربوطه را در محیط استقرار خود تنظیم کنید. در Render، این کار از طریق بخش 

 "Environment Variables" برای هر سرویس انجام می‌شود.

## 2. پیکربندی YouTube API

برای آپلود ویدئوها به یوتیوب، سیستم نیاز به دسترسی به YouTube Data API دارد. این فرآیند شامل ایجاد یک پروژه در Google Cloud Console و فعال‌سازی API است.

### 2.1. دریافت اعتبارنامه YouTube API

1.  **ایجاد پروژه Google Cloud:**
    *   به [Google Cloud Console](https://console.cloud.google.com/) بروید.
    *   یک پروژه جدید ایجاد کنید یا پروژه موجود را انتخاب کنید.
2.  **فعال‌سازی YouTube Data API v3:**
    *   در Google Cloud Console، به بخش "APIs & Services" و سپس "Library" بروید.
    *   "YouTube Data API v3" را جستجو کرده و آن را فعال کنید.
3.  **ایجاد اعتبارنامه OAuth 2.0:**
    *   به بخش "APIs & Services" و سپس "Credentials" بروید.
    *   بر روی "Create Credentials" کلیک کرده و "OAuth client ID" را انتخاب کنید.
    *   نوع برنامه را "Web application" انتخاب کنید.
    *   "Authorized redirect URIs" را به `http://localhost:8000/api/v1/auth/youtube/callback` (برای توسعه محلی) و URL سرویس وب Render شما (مثلاً `https://<your-service-name>.onrender.com/api/v1/auth/youtube/callback`) تنظیم کنید.
    *   پس از ایجاد، `Client ID` و `Client Secret` خود را یادداشت کنید.

### 2.2. تنظیم متغیرهای محیطی YouTube

متغیرهای زیر را در محیط خود (یا در Render) تنظیم کنید:

*   `YOUTUBE_CLIENT_ID`: شناسه کلاینت OAuth 2.0 شما.
*   `YOUTUBE_CLIENT_SECRET`: راز کلاینت OAuth 2.0 شما.
*   `YOUTUBE_DEFAULT_CATEGORY`: شناسه عددی دسته‌بندی پیش‌فرض ویدئوها (مثال: `22` برای People & Blogs).
*   `YOUTUBE_DEFAULT_PRIVACY`: وضعیت حریم خصوصی پیش‌فرض ویدئوها (`public`, `private`, `unlisted`).

## 3. پیکربندی سرویس‌دهنده‌های هوش مصنوعی (LLM)

سیستم از یک لایه انتزاعی برای سرویس‌دهنده‌های LLM استفاده می‌کند. شما می‌توانید از سرویس‌دهنده‌های مختلفی مانند `mock` (برای توسعه)، `ollama` (خودمیزبان)، `openai` یا `deepseek` استفاده کنید.

### 3.1. انتخاب سرویس‌دهنده LLM

متغیر `LLM_PROVIDER` را در محیط خود تنظیم کنید:

*   `LLM_PROVIDER=mock`: برای استفاده از سرویس‌دهنده ماک (توصیه شده برای توسعه و تست اولیه).
*   `LLM_PROVIDER=ollama`: برای استفاده از Ollama (خودمیزبان و رایگان).
*   `LLM_PROVIDER=openai`: برای استفاده از OpenAI.
*   `LLM_PROVIDER=deepseek`: برای استفاده از DeepSeek.

### 3.2. پیکربندی سرویس‌دهنده‌های خاص LLM

*   **برای `mock` provider:**
    *   `LLM_MODEL=mock-llm-v1` (پیش‌فرض).
    *   `LLM_API_KEY=` (نیاز نیست).

*   **برای `ollama` provider:**
    *   `OLLAMA_BASE_URL`: آدرس URL سرویس Ollama شما (مثال: `http://localhost:11434`).
    *   `OLLAMA_MODEL`: نام مدل Ollama که می‌خواهید استفاده کنید (مثال: `llama2`).

*   **برای `openai` provider:**
    *   `OPENAI_API_KEY`: کلید API شما از OpenAI.
    *   `OPENAI_ORG_ID`: شناسه سازمان شما در OpenAI (اختیاری).

*   **برای `deepseek` provider:**
    *   `DEEPSEEK_API_KEY`: کلید API شما از DeepSeek.
    *   `DEEPSEEK_BASE_URL`: آدرس URL پایه API دیپ‌سیک (پیش‌فرض: `https://api.deepseek.com/v1`).

## 4. پیکربندی سرویس‌دهنده‌های ساخت ویدئو (Video Builder)

سیستم از یک لایه انتزاعی برای سرویس‌دهنده‌های ساخت ویدئو استفاده می‌کند. در حال حاضر، فقط `mock` provider پیاده‌سازی شده است.

### 4.1. انتخاب سرویس‌دهنده Video Builder

متغیر `VIDEO_PROVIDER` را در محیط خود تنظیم کنید:

*   `VIDEO_PROVIDER=mock`: برای استفاده از سرویس‌دهنده ماک (توصیه شده برای توسعه و تست اولیه).

### 4.2. پیکربندی سرویس‌دهنده‌های خاص Video Builder

*   **برای `mock` provider:**
    *   `VIDEO_API_KEY=` (نیاز نیست).

## 5. پیکربندی سرویس‌دهنده‌های آپلود (Uploader)

سیستم از یک لایه انتزاعی برای سرویس‌دهنده‌های آپلود ویدئو استفاده می‌کند. در حال حاضر، فقط `mock` provider پیاده‌سازی شده است، اما در آینده می‌توان YouTube API را نیز به آن اضافه کرد.

### 5.1. انتخاب سرویس‌دهنده Uploader

متغیر `UPLOAD_PROVIDER` را در محیط خود تنظیم کنید:

*   `UPLOAD_PROVIDER=mock`: برای استفاده از سرویس‌دهنده ماک (توصیه شده برای توسعه و تست اولیه).

### 5.2. پیکربندی سرویس‌دهنده‌های خاص Uploader

*   **برای `mock` provider:**
    *   `UPLOAD_API_KEY=` (نیاز نیست).

## 6. سایر پیکربندی‌های مهم

علاوه بر موارد فوق، متغیرهای محیطی دیگری نیز وجود دارند که باید تنظیم شوند:

*   `JWT_SECRET_KEY`: یک کلید مخفی قوی و تصادفی برای احراز هویت JWT (بسیار مهم برای امنیت).
*   `DATABASE_URL`: آدرس اتصال به پایگاه داده PostgreSQL (در Render به طور خودکار تنظیم می‌شود).
*   `REDIS_URL`: آدرس اتصال به Redis (در Render به طور خودکار تنظیم می‌شود).
*   `CELERY_BROKER_URL`: آدرس Redis برای Celery Broker (در Render به طور خودکار تنظیم می‌شود).
*   `CELERY_RESULT_BACKEND`: آدرس Redis برای ذخیره نتایج Celery (در Render به طور خودکار تنظیم می‌شود).

**توجه:** همیشه از مقادیر امن و تصادفی برای کلیدهای مخفی (مانند `JWT_SECRET_KEY`) در محیط‌های تولید (production) استفاده کنید.

این راهنما به شما کمک می‌کند تا سرویس‌دهنده‌های مختلف را در سیستم اتوماسیون یوتیوب v3.0 پیکربندی کنید. برای جزئیات بیشتر در مورد هر سرویس‌دهنده، به مستندات مربوطه مراجعه کنید.
